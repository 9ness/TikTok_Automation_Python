# Learnings

* [Fecha] Contexto: Lección / Resolución
* [2026-05-22] Windows + Python runners crashean en `print("🎙️ ...")` por cp1252 default → `UnicodeEncodeError: 'charmap' codec can't encode characters`. Pasa en cualquier emoji impreso en stdout (locutor.py L134 entre muchos). Fix global: `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` al arrancar `src/api/main.py`, antes de imports pesados. Coste de la tarea afectada: 0 (el crash es ANTES de cualquier API call de pago — solo Gemini previo).
* [2026-05-22] Webhook listener se colgaba cada 24-48h. Root cause: `HTTPServer` single-threaded → cualquier conexión lenta (scanner de puertos, GitHub timeout, etc.) bloquea TODAS las requests siguientes; el proceso sigue "active" para systemd pero `/health` da timeout. Fix: `ThreadingHTTPServer` + `daemon_threads=True`. Safety net: `tiktok-webhook-healthcheck.timer` cada 2 min hace `curl --max-time 5 /health || systemctl restart tiktok-webhook`. Solo reinicia el LISTENER (proceso de 11MB en :9000) — los Docker containers tiktok-api/web/caddy son procesos separados, los jobs corriendo no se enteran.
* [2026-05-22] TikTok Shop URL share `vm.tiktok.com/XXXX` redirige a `www.tiktok.com/view/product/{id}?og_info={...JSON-encoded...}&share_region=ES`. El `og_info` trae title + image LIMPIO sin necesidad de scrape JS. Parser en `url_scraper.py:_extract_tiktok_share_params` saca de los query params con `urlparse` + `json.loads(unquote(...))`. Bypassa por completo el bot-detection del HTML de TikTok.
* [2026-05-22] TIKTOK_SHOP_URL_PATTERN debe aceptar cualquier subdominio: `^https?://([\w-]+\.)*tiktok\.com(/.*)?$`. La versión vieja solo aceptaba `www.` y `shop-xx.` y rechazaba `vm.tiktok.com` de los share URLs.
* [2026-05-22] Seedance i2v Atlas: `TIER_DURATION_LIMITS` (config.py) → mín 4s por clip en standard/advanced/pro. Para vídeos <8s solo cabe single_shot. Para ≥8s puede ser multi (2×4s, 4+5, etc.). `strategy="dynamic"` rota fotos (`rotate`) entre clips, `cinematic` no. Pro tier (ref2v) es 1 prompt único con multi-shot INTERNO (hasta 9 refs). Veo 3 nativo 1 toma 10s max.
* [2026-05-22] VideoPreset sub-objetos: TextOverlayStyle (overlay hook con duration_s), SubtitleStyle (karaoke con highlight_color, position siempre bottom_center safe-zone, size 40-52px), CtaArrowStyle (sticker `flecha_negra.mov` / `flecha_roja.mov` de `TIKTOK_EDITOR/Assets/flechas/`, position_x/y_pct, duration final). El runner ya soportaba `OverlaysConfig.cta_arrow` del Editor Auto — sólo había que mapear preset → payload en `applyVideoPreset` y `BulkGenerateDialog.applyPresetToPayload`.
* [2026-05-22] Async preset generation con progress: FastAPI BackgroundTasks + Redis tracker (`preset_gen:{gen_id}` con stage/percent/created_count) + polling 2s en frontend con `usePresetGenStatus`. gen_id persistido en `localStorage[preset-gen:{product_id}]` para sobrevivir refresh navegador. Stages: started → generating_music (5-50%) → generating_scripted (55-90%) → saving (95%) → done/error. Si el user cierra pestaña, la BackgroundTask sigue en el server hasta done.
* [2026-05-22] Gemini cost tracking automático: `_call_with_key` en gemini.py extrae `response.usage_metadata.prompt_token_count` + `candidates_token_count` y llama `record_gemini(input, output, model)`. Si no hay tracker activo el record es no-op (cost_tracking._add_line). Endpoints stateless (analyze-url, photo-grader, preset-generator, variants-generator) envuelven con `start_job(program="tiktok_shop", mode=...)` + `finalize_and_persist()` para que aparezca en `/costs`.
* [2026-05-22] DELETE /products/{id} ahora borra recursivamente la carpeta `TIKTOK_SHOP/_products/<slug>/` en Drive (shutil.rmtree, best-effort — si falla, soft-delete en Redis sigue). Drive Desktop sincroniza el delete a papelera Google Drive (30d recuperable).
* [2026-05-22] `ProductResponse` schema necesita listar EXPLÍCITAMENTE `video_presets: list[dict[str, Any]]`. Pydantic filtra campos no declarados al serializar — sin esta línea los presets se persistían en Redis pero NO llegaban al frontend (mostraba "0 presets" aunque había 28).
* [2026-05-14] Editor Auto: preview de stickers MOV ProRes en frontend requiere transcode → APNG (cache temp, `?as=apng`). Probado libvpx-vp9 con `-pix_fmt yuva420p -auto-alt-ref 0 -metadata:s:v:0 alpha_mode=1`: el encoder reporta yuva420p pero el ffmpeg Windows gyan-build NO escribe los BlockAdditions que Chrome necesita → browser muestra fondo opaco. APNG @ 15fps/200px = ~1.5MB con alpha real (verificado PIL extrema 0-255).
* [2026-05-14] Editor Auto: tool `sticker_arrow` añadida (weight=80, entre cortes 10 y subs 90). Overlay con FFmpeg `[1:v]scale=W*pct,format=rgba[s];[0][s]overlay=x:y:enable='between(t,T0,T1)'` + `-stream_loop -1` para que MOV/WebM cortos se repitan dentro de la ventana. Posición = CENTRO del sticker en % del frame (no top-left) usando `(main_w*px)-(overlay_w/2)`. Detección de gatillo via Whisper local re-transcribe el vídeo post-cortes (timestamps pre-cortes ya no son válidos). Assets en `TIKTOK_EDITOR/Assets/flechas/` (`arrows_folder()`). Endpoint `/stickers/arrows` listado con auth header; `/arrows/{filename}` con auth dual header+query porque `<video src=>` no admite headers custom (mismo patrón que `fonts/file/`).
* [2026-05-14] Editor Auto: tool `silence_cutter_scripted` añadida como hermana del cortador estándar (no flag dentro de la misma tool, para no contaminar el flujo sin guion). Usa Silero VAD + Whisper + `difflib.SequenceMatcher` sobre tokens normalizados (lowercase, sin acentos, sin puntuación) — opcodes `delete/replace` = regiones fuera de guión → cuts. LLM opcional solo para regiones largas ambiguas (≥3 palabras). Mismo `position_weight=10` que `silence_cutter`; coexistencia rechazada vía `TOOL_EXCLUSIVE_GROUPS` en `_validate_steps`. Guion se pasa como Form field en `/enqueue` → `job.params["script"]` → inyectado en `merged_config["script"]` por el orchestrator solo para esa tool.
* [2026-05-06] Presidentes Top N: añadido auto-calibrador de palabras (`src/word_calibrator.py`) que persiste `target_total_words` por tipo de vídeo en Upstash Redis (`tiktokCR:words:presidents:t{N}:hook{0|1}:cr{0|1}`). Tras TTS se mide duración con `ffprobe` y, si está fuera de 60-65s, ajusta proporcionalmente (paso máx ±30 palabras, clamp 120-280) y regenera (hasta 3 intentos). `runners.run_presidents` envuelve guion+audio en bucle de calibración.
* [2026-05-12] Subs sobre vídeo: `merge_edited_text_with_timings` reescrito en 3 iteraciones. Final: frases naturales por pausas ≥ 0.30s con cap 6s/frase (split recursivo) + **anclas matched dentro de cada frase como sub-fronteras**. Sub-segmentos entre anclas se distribuyen char-weighted con floor 80ms/palabra; si un sub-segmento es muy corto, merge bidireccional absorbe vecino. Sobrevive a +60 palabras añadidas con 96% de anclas preservadas dentro de 100ms drift. Path 1:1 directo cuando count idéntico.
* [2026-05-13] Cost tracking unificado en `src/cost_tracking.py`: ContextVar por job + helpers `record_openai_chat / openai_whisper / minimax_tts / atlas_cloud / custom`. `dispatch_job` envuelve cada runner en `start_job`/`finalize_and_persist`. Redis (prefijo `tiktok_shop:`): `cost:job:{id}`, `cost:index:{program}:{YYYY-MM}`, `cost:by_user:{u}`, `cost:by_product:{p}`. Endpoint `GET /api/v1/stats/jobs` con filtros mes/programa/modo/user/product → summary + lista. Página `/costs` en frontend con tabla expandible por job. Tarifas actualizables en constantes top del módulo. Convención obligatoria para nuevos modos documentada en CLAUDE.md.
* [2026-05-13] Editor Auto (Programa 3): herramientas componibles tipo plugin con `BaseTool` Protocol + REGISTRY + reorden determinista por `TOOL_POSITION_WEIGHTS` (silence_cutter peso 10 antes que subs_auto 90 porque cortar mueve timestamps). La UI consume `GET /tools` y genera formularios desde `config_schema` declarativo — añadir una herramienta nueva no requiere tocar frontend. Silero VAD ONNX (paquete `silero-vad`) evita PyTorch full. `cost_tracking.record_openai_chat` extendido con `_OPENAI_CHAT_RATES` (gpt-4o $2.50/$10.00 por 1M tokens) — match por prefix del model name.
* [2026-05-18] Construcción POV (nicho 4 CR): Gemini 2.5 Pro upload de vídeo vía Files API requiere polling de `uploaded.state.name` hasta `"ACTIVE"` (timeout 180s, step 2s) ANTES de `generate_content` — si llamas mientras está `PROCESSING` falla con "file is not in active state". `genai.delete_file(uploaded.name)` tras la llamada para no acumular cuota Files. Pipeline: 1) ffprobe duración → calcular `target_chars` (15.5 chars/s EN, cola silencio 4s, mín 200); 2) Gemini → guion EN 1ª persona; 3) MiniMax `generate_single_audio` con voice_id; 4) ffmpeg `-c:v copy -c:a aac -shortest` para mux audio nuevo sobre vídeo original; 5) Whisper sobre la narración con `initial_prompt=script_text` para boost; 6) ffmpeg `scale*1.08+crop+eq=saturation` + metadata strip `-map_metadata -1 -flags +bitexact`; 7) `render_subtitles_on_video` karaoke. Voice cloning expuesto en endpoint global `/api/v1/voices/clone` (sube MP3 → MiniMax `voice_clone` API → `VoiceRepo.save` persistente) + `/voices/{id}/sample` sin auth para `<audio src>` de audición. Preset EN expandido a 40 voces en `tiktok_shop/config.py:DEFAULT_VOICE_PRESETS_EN`.
* [2026-05-19] Construcción POV — fix "última palabra en bucle hasta fin del vídeo": MoviePy `VideoFileClip` + `write_videofile` re-encodea el audio con `AudioFileClip`; cuando el audio del input es más corto que el vídeo (narración 53s + cola silenciosa 8s) y le pide samples más allá del fin real, el reader devuelve el último buffer loopeado en lugar de silencio. Fix en `src/construccion_pov/pipeline.py:_mux_audio_over_video`: usar `-filter_complex "[1:a]apad[aout]"` + `-shortest` (en lugar de `-t video_dur` con audio sin padding) → el track de audio del MP4 queda exactamente igual a video_dur con silencio limpio tras la narración, y MoviePy no tiene que extrapolar.
* [2026-05-19] Fuentes en container API — `Dockerfile.api` no instalaba TTFs y `python:3.11-slim` viene casi sin ellos → en producción solo aparecían 3 fuentes en el selector (las 2 bundled del repo + 1 que arrastraba ffmpeg) y los presets con `C:\Windows\Fonts\impact.ttf` fallaban con "fuente no existe en el registry". Fix: añadir `fontconfig fonts-dejavu fonts-liberation fonts-noto-color-emoji` + repo `contrib` + `debconf-set-selections` para EULA + `ttf-mscorefonts-installer` al Dockerfile.api (paquete vive en contrib, no main). Adicional: `fonts_registry.find_by_path` usaba `os.path.basename` que en Linux NO trata `\` como separador → frontend mandando paths Windows guardados en presets viejos no matcheaban. Helper `_cross_platform_basename` divide manualmente por `/` y `\` antes de comparar.
* [2026-05-19] sticker_arrow FFmpeg crash — `main_w`/`main_h` son variables de `scale2ref`/`overlay`, NO válidas en `scale` plano. ffmpeg 5.x (debian-bookworm, el del Dockerfile.api) rechaza estricto: "Expressions with scale2ref variables are not valid in scale filter". Funcionaba en local con ffmpeg 6.x/7.x pero peta en producción. Fix en `src/editor_auto/tools/sticker_arrow.py:_apply_overlay_ffmpeg`: probe width del input con ffprobe (`_probe_video_size`) y usar literal en el `scale` del sticker (`scale={W*sw}:-2`). En `overlay` `main_w`/`main_h` SÍ son válidas → no se tocan. Fallback 1080 si ffprobe falla.
* [2026-05-19] sticker_arrow match policy + fuzzy — antes solo cogía la PRIMERA ocurrencia del trigger en el último 50% del vídeo → cuando el speaker decía "carrito" varias veces, solo se ponía 1 flecha y normalmente no en el momento esperado. Además Whisper transcribe "carrito"→"carito" (se come una RR) → keyword exact-match fallaba. Refactor: `match_strategy` config (`first|last|all`, default `last`) + `fuzzy_match` config (edit-distance ≤1 para keywords ≥5 chars). `_find_keyword_matches` devuelve lista, no single. `_apply_overlay_ffmpeg` acepta `windows: list[tuple[float,float]]` y concatena con `+` en el `enable=` expr (OR lógico ffmpeg). Helper `_merge_overlapping_windows` funde ventanas solapadas para no duplicar overlays.
* [2026-05-19] silence_cutter detección auto de estilo (monólogo vs conversación) — heurística gratis sobre output de Silero VAD: `mean_segment_dur` < 4s Y `turn_gap_ratio` (suma de pausas 0.4-1.5s sobre duración) > 0.05 → conversación; resto → monólogo. Cero coste extra (los datos ya están). Config `auto_detect_style: bool` (default True) + `manual_style: enum` para override manual. En conversación se sube `inter_word_gap_threshold_s` 0.5→1.2 y `inter_word_gap_keep_ms` 200→350: preserva turn-taking natural en vez de comerse cada gap entre turnos. Decisión y métricas se loguean explícitamente para que el operador entienda por qué se aplicó un modo u otro.
* [2026-05-19] subs_auto precisión Whisper — default `reference_text` poblado con vocabulario TikTok Shop ES (carrito, link, descuento, código, oferta, envío gratis, etc.) → se pasa como `initial_prompt` a Whisper y reduce errores de transcripción en palabras del nicho. Toggle nuevo `audio_denoise` (default OFF) que aplica ffmpeg `afftdn=nr=12:nf=-25` antes del transcribe — mejora 5-10% en audios sucios pero +5-10s de pipeline. Si falla, fallback al audio original sin abortar.
* [2026-05-19] silence_cutter_scripted fallback automático sin guion — antes la tool fallaba con RuntimeError si `job.params["script"]` estaba vacío. Ahora instancia `SilenceCutterTool()` con sus defaults + override de campos comunes (`vad_enabled, min_silence_ms, padding_ms, ai_language, whisper_model_size, output_aspect, post_audit_enabled`) y delega. Loguea el fallback claramente para que el operador vea en la cola "No se ha encontrado guion → fallback a modo SIN guion". Permite configurar siempre la versión scripted y olvidarse: si hay guion → diff transcript↔guion; si no → cortes VAD/IA normales.
* [2026-05-19] UserFlowEditor pickers — `FontPickerField` y `StickerPickerField` mostraban paths/filenames raw como label visible del `<option>` seleccionado. Si la config se creó en local Windows con `font_path=D:\Proyectos_Personales\…\Rubik-Bold.ttf` y se abre en producción Linux (paths `/usr/share/fonts/…/Rubik-Bold.ttf`), el `find(f.path===current)` fallaba y se renderizaba el path Windows entero como label. Fix: helper `crossPlatformBasename` (divide por `/` y `\`) + resolución por basename como fallback en FontPicker; helper `prettyFilename` que convierte `flecha_roja.mov` → "Flecha roja" en StickerPicker. Si nada matchea se muestra solo el basename con sufijo `·sin resolver`, no la ruta entera.
* [2026-05-19] Whisper default `large-v3` en todas las tools Editor Auto — antes era `small` (rápido, ~1GB RAM, pero menos preciso). Cambio aplica a `silence_cutter`, `silence_cutter_scripted`, `sticker_arrow` y `subs_auto`, tanto en `default_config` como en los `.get(..., "small")` defensivos del `run()`. Coste: ~3-5x más lento por job y ~6-8GB RAM con int8 quantization (faster-whisper). Beneficio: precisión notablemente superior en audio rápido, conversación, ruido de fondo. Si en producción Hetzner CX32 (8GB total) OOMea o tarda demasiado, el operador baja a `medium` por config UI (sin tocar código).
* [2026-05-19] Drive sharing `revoke_permission` con cascade — Drive API devuelve `403 cannotDeletePermission` si intentas borrar un permiso heredado en una carpeta hija. El `permission_id` que el frontend ve en `entrada/` puede ser el mismo perm que vive en `<usuario>/` (raíz del usuario): la herencia lo expone en hijos pero solo se puede borrar donde realmente está. Fix en `src/editor_auto/services/drive_sharing.py:revoke_permission`: cascade hijo→padre (subcarpeta → usuario → Usuarios → TIKTOK_EDITOR). En cada nivel intenta el delete; si Drive responde con `cannotDeletePermission`/`notFound` sigue subiendo. Devuelve el nombre del nivel donde se revocó realmente para que el frontend pueda avisar si cascadeó más arriba de lo esperado. Endpoint `DELETE /users/{id}/shares/{permId}` ahora devuelve `revoked_at_level` en la respuesta.
* [2026-05-19] Encolar dialog (Editor Auto) — guion ahora OPCIONAL en el modal. Antes era "obligatorio" con `disabled={!ready}` bloqueando el botón Encolar. Con el fallback scripted→non-scripted ya implementado (commit `0b6ee7f`), el guion vacío es válido: el backend cae al modo VAD/IA automáticamente y loguea la decisión. Textarea sigue ahí para quien quiera pegar guion manual, pero el placeholder ahora dice "vacío = modo sin guion". El backend ya detecta el companion `<stem>.txt` en entrada/ via `_script_companion` y lo aplica solo si existe.
* [2026-05-19] Batch enqueue Editor Auto — botón "Encolar todos (N)" en cabecera del tab entrada/ cuando hay ≥2 vídeos. Procesa secuencialmente con `mutateAsync` en loop (la cola del worker ya es secuencial, así que paralelismo en el dispatch no aporta). Cada vídeo se encola con `script=""` → backend usa companion `.txt` si existe, sino fallback a modo sin guion. Dialog muestra desglose previo: cuántos tienen companion (modo premium) vs cuántos no (modo VAD/IA). Toast resumen al final: success si todos OK, warning si fallos parciales, error si todos fallan. `e.preventDefault()` en `onClick` del AlertDialogAction evita cierre automático del modal antes de terminar el batch.
* [2026-05-19] Encolar SIN modal + sin validación backend — el botón "Encolar" individual ya no abre AlertDialog. Click → POST `/folders/enqueue` directo con `script=""`. Backend (`src/api/routers/editor_auto/folders.py`) ya NO bloquea con ValidationError si el flow es scripted y no hay guion: la lógica de fallback en `silence_cutter_scripted.run()` (commit `0b6ee7f`) detecta script vacío y delega al cutter sin guion automáticamente. Tooltip del botón explica el modo activo según haya companion `.txt` o no. Para usar modo con guion, el operador sube `<stem>.txt` junto al vídeo en `entrada/` (autodetect en el listing).
* [2026-05-19] Auto-enqueue watcher (Editor Auto) — toggle `auto_enqueue` por usuario en el modelo `EditorUser`. Cuando activo, un background task lanzado desde el `lifespan` de FastAPI (`src/editor_auto/services/auto_enqueue_watcher.py`) hace polling cada 30s a la carpeta `entrada/` de los usuarios con flag ON y encola los vídeos nuevos. Reglas de seguridad: (a) `mtime` mínimo 60s para evitar uploads en curso; (b) si el flow tiene `silence_cutter_scripted` y NO hay companion `.txt`, margen extra 180s por si el cliente sube el guion después del vídeo; (c) try/except en cada paso — si move falla, vídeo sigue en entrada/; si move OK pero `queue.enqueue` falla, rollback cola→entrada; (d) errores per-archivo se loguean sin detener el loop. Frontend: Switch + Zap badge en cada user list item.
* [2026-05-19] silence_cutter `ai_pass2_openai_enabled=True` por defecto — antes solo Gemini en pass2 (default balanced). Cambio a PRO consenso (OpenAI + Gemini ambos en pass2). Coste por vídeo sube ~+$0.008/min pero pillamos false-starts que escapan a una sola pasada y tenemos red de seguridad ante non-determinismo de un modelo. El usuario puede desactivar uno de los dos toggles desde la UI si quiere bajar costes.
