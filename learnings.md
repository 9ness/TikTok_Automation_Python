# Learnings

* [Fecha] Contexto: Lección / Resolución
* [2026-05-14] Editor Auto: preview de stickers MOV ProRes en frontend requiere transcode → APNG (cache temp, `?as=apng`). Probado libvpx-vp9 con `-pix_fmt yuva420p -auto-alt-ref 0 -metadata:s:v:0 alpha_mode=1`: el encoder reporta yuva420p pero el ffmpeg Windows gyan-build NO escribe los BlockAdditions que Chrome necesita → browser muestra fondo opaco. APNG @ 15fps/200px = ~1.5MB con alpha real (verificado PIL extrema 0-255).
* [2026-05-14] Editor Auto: tool `sticker_arrow` añadida (weight=80, entre cortes 10 y subs 90). Overlay con FFmpeg `[1:v]scale=W*pct,format=rgba[s];[0][s]overlay=x:y:enable='between(t,T0,T1)'` + `-stream_loop -1` para que MOV/WebM cortos se repitan dentro de la ventana. Posición = CENTRO del sticker en % del frame (no top-left) usando `(main_w*px)-(overlay_w/2)`. Detección de gatillo via Whisper local re-transcribe el vídeo post-cortes (timestamps pre-cortes ya no son válidos). Assets en `TIKTOK_EDITOR/Assets/flechas/` (`arrows_folder()`). Endpoint `/stickers/arrows` listado con auth header; `/arrows/{filename}` con auth dual header+query porque `<video src=>` no admite headers custom (mismo patrón que `fonts/file/`).
* [2026-05-14] Editor Auto: tool `silence_cutter_scripted` añadida como hermana del cortador estándar (no flag dentro de la misma tool, para no contaminar el flujo sin guion). Usa Silero VAD + Whisper + `difflib.SequenceMatcher` sobre tokens normalizados (lowercase, sin acentos, sin puntuación) — opcodes `delete/replace` = regiones fuera de guión → cuts. LLM opcional solo para regiones largas ambiguas (≥3 palabras). Mismo `position_weight=10` que `silence_cutter`; coexistencia rechazada vía `TOOL_EXCLUSIVE_GROUPS` en `_validate_steps`. Guion se pasa como Form field en `/enqueue` → `job.params["script"]` → inyectado en `merged_config["script"]` por el orchestrator solo para esa tool.
* [2026-05-06] Presidentes Top N: añadido auto-calibrador de palabras (`src/word_calibrator.py`) que persiste `target_total_words` por tipo de vídeo en Upstash Redis (`tiktokCR:words:presidents:t{N}:hook{0|1}:cr{0|1}`). Tras TTS se mide duración con `ffprobe` y, si está fuera de 60-65s, ajusta proporcionalmente (paso máx ±30 palabras, clamp 120-280) y regenera (hasta 3 intentos). `runners.run_presidents` envuelve guion+audio en bucle de calibración.
* [2026-05-12] Subs sobre vídeo: `merge_edited_text_with_timings` reescrito en 3 iteraciones. Final: frases naturales por pausas ≥ 0.30s con cap 6s/frase (split recursivo) + **anclas matched dentro de cada frase como sub-fronteras**. Sub-segmentos entre anclas se distribuyen char-weighted con floor 80ms/palabra; si un sub-segmento es muy corto, merge bidireccional absorbe vecino. Sobrevive a +60 palabras añadidas con 96% de anclas preservadas dentro de 100ms drift. Path 1:1 directo cuando count idéntico.
* [2026-05-13] Cost tracking unificado en `src/cost_tracking.py`: ContextVar por job + helpers `record_openai_chat / openai_whisper / minimax_tts / atlas_cloud / custom`. `dispatch_job` envuelve cada runner en `start_job`/`finalize_and_persist`. Redis (prefijo `tiktok_shop:`): `cost:job:{id}`, `cost:index:{program}:{YYYY-MM}`, `cost:by_user:{u}`, `cost:by_product:{p}`. Endpoint `GET /api/v1/stats/jobs` con filtros mes/programa/modo/user/product → summary + lista. Página `/costs` en frontend con tabla expandible por job. Tarifas actualizables en constantes top del módulo. Convención obligatoria para nuevos modos documentada en CLAUDE.md.
* [2026-05-13] Editor Auto (Programa 3): herramientas componibles tipo plugin con `BaseTool` Protocol + REGISTRY + reorden determinista por `TOOL_POSITION_WEIGHTS` (silence_cutter peso 10 antes que subs_auto 90 porque cortar mueve timestamps). * [2026-05-18] Construcción POV (nicho 4 CR): Gemini 2.5 Pro upload de vídeo vía Files API requiere polling de `uploaded.state.name` hasta `"ACTIVE"` (timeout 180s, step 2s) ANTES de `generate_content` — si llamas mientras está `PROCESSING` falla con "file is not in active state". `genai.delete_file(uploaded.name)` tras la llamada para no acumular cuota Files. Pipeline: 1) ffprobe duración → calcular `target_chars` (15.5 chars/s EN, cola silencio 4s, mín 200); 2) Gemini → guion EN 1ª persona; 3) MiniMax `generate_single_audio` con voice_id; 4) ffmpeg `-c:v copy -c:a aac -shortest` para mux audio nuevo sobre vídeo original; 5) Whisper sobre la narración con `initial_prompt=script_text` para boost; 6) ffmpeg `scale*1.08+crop+eq=saturation` + metadata strip `-map_metadata -1 -flags +bitexact`; 7) `render_subtitles_on_video` karaoke. Voice cloning expuesto en endpoint global `/api/v1/voices/clone` (sube MP3 → MiniMax `voice_clone` API → `VoiceRepo.save` persistente) + `/voices/{id}/sample` sin auth para `<audio src>` de audición. Preset EN expandido a 40 voces en `tiktok_shop/config.py:DEFAULT_VOICE_PRESETS_EN`.
* [2026-05-19] Construcción POV — fix "última palabra en bucle hasta fin del vídeo": MoviePy `VideoFileClip` + `write_videofile` re-encodea el audio con `AudioFileClip`; cuando el audio del input es más corto que el vídeo (narración 53s + cola silenciosa 8s) y le pide samples más allá del fin real, el reader devuelve el último buffer loopeado en lugar de silencio. Fix en `src/construccion_pov/pipeline.py:_mux_audio_over_video`: usar `-filter_complex "[1:a]apad[aout]"` + `-shortest` (en lugar de `-t video_dur` con audio sin padding) → el track de audio del MP4 queda exactamente igual a video_dur con silencio limpio tras la narración, y MoviePy no tiene que extrapolar.
